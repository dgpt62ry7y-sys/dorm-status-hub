# ntfy 宿舍共享通知设计

日期：2026-11-21

状态：已确认，开始实施

## 产品决策

- 每个宿舍一个共享 ntfy Topic。
- Topic 由服务端生成，只向已验证成员返回。
- 公共 ntfy.sh Topic 不是访问控制频道，知道 Topic 的人可以订阅、读取和伪造消息。
- 昵称、留言、预计时间、安静人数可以发送到 ntfy.sh。
- 所有状态通知优先级为 `4`。
- 修改者本人也会收到通知。
- 自动过期恢复正常活动不发送通知。
- 点击通知打开网页功能暂不实现，后续再考虑。
- 不部署线上环境。

## 安静人数

- 将表示睡觉中与专注学习总人数的“休息人数”统一改为“安静人数”。
- 只统计当前有效的 `sleep` 和 `focus`。
- `normal`、`away`、已过期状态不计入。
- 分母使用宿舍容量 4 或 6。
- 页面、状态说明、通知和测试使用同一规则。

## Topic 模型

- Topic 格式为 `dormsync-` 加 256-bit 随机 base64url 字符串。
- Topic 总长度不超过 64。
- 新宿舍创建时生成 `ntfyTopic` 和 `ntfyTopicUpdatedAt`。
- 存量宿舍在首次访问通知设置时惰性生成。
- 并发初始化使用 `systemSettings` 中的唯一抢占记录保证最终 Topic 一致。
- 普通 `getState` 和创建宿舍响应不返回 Topic。
- Topic 不进入日志、README、静态配置或普通状态接口。

## 通知设置 API

- `getNotificationSettings`：成员令牌验证后读取当前宿舍 Topic。
- `rotateNotificationTopic`：仅房主可调用，生成新 Topic。
- `sendTestNotification`：仅房主可调用，一分钟最多一次。
- 通知设置返回服务器、Topic、Topic 更新时间、需要轮换提示和房主标识。
- 不返回虚假的设备订阅状态。

## 订阅体验

- 设置页新增“宿舍通知”。
- Topic 默认遮挡，用户主动显示后可复制。
- Android 使用 `ntfy://ntfy.sh/<topic>?display=<roomName>` 深链。
- iOS 提供复制 Topic、安装 App 和手动添加步骤，不宣称自动订阅。
- 微信 WebView 中始终保留复制 Topic 兜底。
- Topic 轮换提示为非阻塞提醒。
- 成员被移除或退出时设置 `ntfyTopicNeedsRotation`，提示房主手动轮换，不自动轮换。
- 不记录也不展示服务端“已订阅”状态。

## 通知触发

- 仅在成员主动 `updateStatus` 且 status、note、endAt 至少一项实际变化时发送。
- 一次更新只发送一条。
- `getState`、`buildState`、`expireStatuses` 不发送通知。
- 创建宿舍、加入宿舍、改昵称、设备管理和成员管理不发送状态通知。
- 状态保存成功后使用最新 state 计算安静人数。
- ntfy 发送失败不回滚状态，并返回非阻塞警告。
- ntfy 请求使用约 3 秒超时，不自动多次重试。

## 通知内容

统一标题：`DormSync · 宿舍状态更新`

时间统一使用北京时间：

- 同一自然日显示 `HH:mm`。
- 发送时预计时间在下一自然日显示 `明天 HH:mm`。
- 过了午夜后，同一天的时间不再显示“明天”。

正文使用同一套纯文本 Emoji 模板，ntfy 和 Bark 共用：

- 睡觉中：`💤 昵称 正在睡觉`
- 专注学习：`📚 昵称 正在专注学习`
- 外出：`🚶 昵称 已外出`
- 正常活动：`🏠 昵称 已恢复正常活动`
- 预计时间行：`⏰` 或 `🏠`
- 留言行：`💬`
- 安静人数行：`🤫`
- 正常活动更新时间行：`🕒`

可选行留空时整行省略，不使用 Markdown，不插入空行。昵称和留言中的换行、制表符会折叠为普通空格，避免用户输入破坏通知结构。

睡觉中/专注学习：

- 成员昵称和状态描述。
- 有值时显示预计时间。
- 有值时显示留言。
- 显示当前安静人数 / 宿舍容量。
- 显示保持安静提醒。

正常活动/外出：

- 不显示安静人数和保持安静提醒。
- 外出有预计回寝时间时显示。
- 正常活动显示实际更新时间。
- 有值时显示留言。

## ntfy 请求

- 发布地址由服务端配置，默认 `https://ntfy.sh`。
- 使用 Node.js 内置 `fetch`。
- Header 使用 `Priority: 4`、`Tags: bell`，正文保持纯文本默认格式。
- 中文标题使用 RFC 2047 UTF-8 Base64 编码。
- 正文使用 UTF-8 纯文本。
- 日志只记录脱敏后的错误摘要。

## 本地测试

- 本地六账号测试版使用本地通知收件箱，不向真实 ntfy.sh 发布。
- 收件箱显示标题、Priority、正文和接收时间。
- 重置虚拟测试数据时同时清空收件箱。
- 自动化测试全部 mock ntfy 请求。

## 测试重点

- 安静人数统计和命名。
- 四种状态下主动更新的通知内容。
- 只改留言、只改时间、无变化、自动过期。
- Topic 不进入创建响应。
- 同宿舍成员得到同一 Topic，不同宿舍不同。
- Topic 并发初始化和轮换权限。
- 测试通知权限和频率。
- ntfy 失败不回滚状态。
- 正文不包含令牌、恢复码、邀请码或 Topic。
- 本地收件箱截获且不访问真实 ntfy。
- 现有账号、容量、版本公告和本地工具测试通过。

## 人工验证

- iPhone 和 Android 真机订阅同一 Topic。
- 前台、后台、锁屏、省电模式和微信浮窗外送达。
- 记录延迟和失败，不承诺所有设备即时送达。
