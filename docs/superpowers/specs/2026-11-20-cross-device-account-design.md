# 宿舍状态共享站跨设备账号设计

日期：2026-11-20

状态：已实现，等待发布

## 目标

把当前“一台设备一个成员令牌”的身份模型升级为“一个成员账号绑定多台可信设备”。

完成后需要满足：

- 同一个人的手机和电脑可以同时使用同一个成员身份。
- 任一设备修改状态后，其他设备在现有 5 秒同步周期内看到更新。
- 新设备可以通过短时绑定码加入已有账号。
- 旧设备丢失时，可以通过账号恢复码在新设备恢复账号。
- 用户可以查看并撤销账号下的其他设备。
- 现有用户的令牌继续有效，升级时不强制重新加入宿舍。

## 非目标

- 不读取或识别真实微信号、手机号或微信账号资料。
- 不依赖微信公众号、网页授权、小程序 AppID 或 AppSecret。
- 不把一个账号扩展到多个宿舍；一个成员仍然只属于一个宿舍。
- 不提供短信、微信或浏览器推送通知。
- 不自动迁移用户在其他浏览器中已经创建的错误成员身份。

## 账号模型

### 成员账号

`members` 集合中的一条记录继续代表一个宿舍成员账号。宿舍容量仍按成员账号计算，绑定多台设备不会占用新的宿舍床位。

新增字段：

- `recoveryCodeHash`：账号恢复码的 SHA-256 哈希。
- `recoveryCodeUpdatedAt`：恢复码最近生成时间。

成员被移除、退出宿舍或宿舍关闭后，该成员的全部设备会话都应失效。

### 设备会话

新增 `deviceSessions` 集合。每个浏览器或手机对应一个独立会话：

- `id`
- `memberId`
- `roomId`
- `tokenHash`
- `label`
- `createdAt`
- `lastSeenAt`
- `revokedAt`

约束：

- 每个成员账号最多保留 5 个未撤销会话。
- 每个设备会话使用独立随机令牌。
- 数据库只保存令牌哈希。
- 当前设备可以撤销其他设备；退出当前设备不会退出宿舍。

### 设备绑定码

新增 `deviceLinks` 集合：

- `id`
- `memberId`
- `roomId`
- `codeHash`
- `createdBySessionId`
- `createdAt`
- `expiresAt`
- `usedAt`
- `revokedAt`

绑定码规则：

- 8 位字符，使用排除易混淆字符的大写字母和数字。
- 有效期 5 分钟。
- 只能使用一次。
- 同一成员生成新绑定码时，旧的未使用绑定码立即失效。
- 数据库只保存绑定码哈希。

## 恢复码

- 恢复码为 20 位随机字符，界面按 `XXXX-XXXX-XXXX-XXXX-XXXX` 分组展示。
- 创建或加入宿舍成功后返回一次原文，前端要求用户保存。
- 数据库只保存恢复码哈希。
- 恢复码长期有效，直到用户主动重新生成。
- 重新生成后，旧恢复码立即失效。
- 当前设备丢失且没有恢复码时，只能由房主移除该成员后重新加入，原成员身份无法恢复。

## API

保留现有宿舍、成员和状态 API，新增以下操作。

### 创建绑定码

`createDeviceLink`

- 需要有效成员令牌。
- 生成短时绑定码并返回原文、过期时间。
- 返回绑定码只在创建时出现一次。

### 绑定新设备

`claimDeviceLink`

- 不需要成员令牌，需要绑定码。
- 校验绑定码哈希、有效期、使用状态和设备数量上限。
- 成功后创建新设备会话和随机成员令牌，并返回与现有登录接口一致的会话结果。
- 绑定码立即标记为已使用。

### 恢复账号

`recoverAccount`

- 不需要成员令牌，需要账号恢复码。
- 校验恢复码哈希和设备数量上限。
- 成功后创建新设备会话并返回会话结果。
- 恢复码本身不消耗，可继续用于后续设备。

### 设备列表

`listDevices`

- 需要有效成员令牌。
- 返回设备 ID、标签、创建时间、最近活动时间和当前设备标记。
- 不返回任何令牌或令牌哈希。

### 撤销设备

`revokeDevice`

- 需要有效成员令牌。
- 可以撤销账号下任意设备会话。
- 撤销当前设备后，前端清除本地令牌并返回登录首页，但不退出宿舍。

### 重新生成恢复码

`rotateRecoveryCode`

- 需要有效成员令牌。
- 生成新的恢复码，更新恢复码哈希和时间。
- 返回新恢复码原文一次。

### 创建和加入结果

`createRoom` 与 `joinRoom` 继续返回 `memberToken` 和 `state`，并增加一次性的 `recoveryCode`。

## 身份校验与旧账号迁移

新的令牌校验顺序：

1. 查询 `deviceSessions.tokenHash` 且会话未撤销。
2. 如果未找到，兼容查询现有 `members.memberTokenHash`。
3. 旧令牌命中时自动创建对应的设备会话，原令牌继续有效。

迁移要求：

- 不批量改写现有成员记录。
- 不要求现有用户重新加入宿舍。
- 旧账号首次使用新版本时自动获得设备会话。
- 旧账号可以在设置页主动生成恢复码。
- 新创建账号同时写入成员记录和设备会话。

## 前端体验

### 登录首页

保留“创建宿舍”和“加入宿舍”，增加：

- “绑定已有账号”
- “使用恢复码恢复”

绑定入口只要求输入 8 位绑定码。恢复入口只要求输入 20 位恢复码。

### 新账号完成页

创建或加入成功后：

1. 展示账号恢复码。
2. 提供复制按钮。
3. 明确提示这是找回账号的唯一长期凭证。
4. 用户确认已保存后进入宿舍。

### 设置页

增加“账号与设备”区域：

- 绑定新设备：生成并复制 5 分钟有效绑定码。
- 恢复码：重新生成，并展示安全提示。
- 登录设备：展示设备标签、最近活动时间和当前设备标记。
- 其他设备：支持单独撤销。
- 当前设备：支持退出当前设备但保留宿舍成员身份。

原有“退出宿舍”继续表示永久离开宿舍，并与“退出当前设备”明确区分。

## 错误处理

新增稳定的 API 错误码：

- `DEVICE_LINK_INVALID`
- `DEVICE_LINK_EXPIRED`
- `DEVICE_LINK_USED`
- `RECOVERY_CODE_INVALID`
- `DEVICE_LIMIT_REACHED`
- `DEVICE_SESSION_REVOKED`

前端应根据错误码展示明确操作提示，不显示通用网络错误。

## 安全规则

- 前端不接收或保存绑定码哈希、恢复码哈希和其他用户的设备令牌。
- 绑定码和恢复码都是高熵随机值，数据库不保存原文。
- 绑定码短时、单次使用，新码会撤销旧码。
- 恢复码不随普通状态接口返回。
- 被移除或退出宿舍时撤销该成员全部设备会话。
- 普通成员不能查看其他成员的设备列表。
- 房主移除成员后，该成员已经打开的其他设备在下一次请求时失效。
- 五个设备上限按未撤销会话计算。

## 兼容性与部署

- `ensureCollections` 增加 `deviceSessions` 和 `deviceLinks`。
- 新集合在首次调用云函数时自动创建。
- 先部署云函数，再部署前端，避免新界面调用不存在的 API。
- `npm run deploy` 仍然可以一次完成构建和发布。
- 旧版前端调用新云函数时保持兼容。
- 新版前端可以识别旧令牌并完成会话迁移。

## 测试计划

### API

- 新账号创建后返回恢复码，数据库中不存在恢复码原文。
- 使用有效绑定码创建第二个设备会话。
- 绑定码过期后不能使用。
- 绑定码使用后不能再次使用。
- 生成新绑定码后旧绑定码失效。
- 同一账号最多创建 5 个设备会话。
- 使用恢复码创建新设备会话。
- 重新生成恢复码后旧恢复码失效。
- 撤销一个设备后其他设备不受影响。
- 被移除成员的设备会话全部失效。
- 退出宿舍保留和现有逻辑一致。
- 旧版成员令牌首次请求后自动迁移为设备会话。

### 前端

- 两台浏览器绑定同一账号后状态同步。
- 两台设备同时在线时任一设备都能修改状态。
- 当前设备标记正确。
- 复制绑定码和恢复码成功。
- 过期、无效和已使用绑定码显示对应提示。
- 退出当前设备后回到登录首页，但其他设备仍可使用。
- 320px、390px 和桌面布局正常。
- 页面无控制台运行错误。

## 验收标准

- 同一个成员账号可以同时在手机和电脑使用。
- 不需要微信公众号或微信网页授权。
- 现有用户升级后不掉线。
- 新设备绑定一次后可以长期使用。
- 有恢复码时，即使旧设备丢失也能重新获得账号。
- 所有长期令牌、绑定码和恢复码都以哈希形式存储。
- 设备管理和退出流程不会误将成员移出宿舍。
