# 设置页功能更新日志设计

日期：2026-11-21

状态：已确认，开始实施

## 产品决策

- 不新增独立路由或页面。
- 在设置页现有“版本”行下方增加“功能更新日志”。
- 更新日志默认收起，点击后原地展开，再次点击收起。
- 不显示 `NEW`；现有机制只能在临时公告弹窗中可靠判断未读状态，无法作为长期设置项标记。
- 现有版本数据没有经过确认的发布日期，因此不显示日期。

## 数据来源

- `cloudfunctions/api/releases.json` 是唯一版本内容数据源。
- `cloudfunctions/api/releases.cjs` 只负责兼容云函数现有的 `require` 读取方式。
- 前端直接导入同一 JSON，并按语义化版本号从新到旧展示。
- 打开或展开更新日志不请求云函数、不读取数据库，也不更新公告已读状态。

## 页面结构

- 设置页继续展示动态读取的当前版本。
- “功能更新日志”显示历史版本数量。
- 展开后按时间倒序展示版本号、更新条目和最新版本标记。
- 视觉沿用设置列表、现有字体和颜色体系，使用轻量纵向时间线。
- 默认收起，避免设置页在手机端过长。

## 不受影响的行为

- 版本更新弹窗的触发、合并规则和确认逻辑不变。
- 公告已读版本、同一账号只提醒一次以及设备领取规则不变。
- 宿舍状态、成员、设备、通知和数据库结构不变。

## 验证

- 自动测试确认最新版本等于项目版本、条目不重复且非空、语义版本顺序正确。
- 自动测试确认前端和云函数读取同一 JSON。
- 运行 `npm test`、`npm run check:release` 和 `npm run build`。
- 检查 320px、375/390px 和桌面宽度下展开区域不溢出。
- 不执行 CloudBase 部署。
