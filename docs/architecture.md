# 宿舍状态共享站架构

## 身份

- 每名成员通过创建宿舍或邀请码首次加入，成员记录代表稳定账号。
- 服务端为每台设备生成独立随机成员令牌，前端保存在当前浏览器的 `localStorage`。
- PostgreSQL 的 `deviceSessions` 只保存设备令牌的 SHA-256 哈希。
- 已登录设备可以生成 5 分钟有效、只能使用一次的 8 位绑定码。
- 新设备通过绑定码加入同一成员账号，不增加宿舍成员数量。
- 每个账号最多保留 5 个有效设备会话。
- 账号恢复码为一次性展示的 20 位随机值，数据库只保存哈希，可用于旧设备丢失后恢复账号。
- 成员数据读取、状态修改和成员管理操作都必须携带有效设备令牌。

## 数据

CloudBase PostgreSQL 开启 Document 扩展后，使用五个文档集合：

- `rooms`：宿舍名称、邀请码、创建者、四人或六人容量、房型变更通知和关闭状态。
- `members`：成员昵称、身份、恢复码哈希、容量通知投递状态、加入时间和活跃状态。
- `statuses`：每个成员当前唯一的宿舍状态。
- `deviceSessions`：成员账号下的设备令牌哈希、设备标签、最近在线和撤销状态。
- `deviceLinks`：短时设备绑定码哈希、有效期和使用状态。
- `releaseClaims`：全站版本公告的账号级领取和确认记录。

## API

- `dormsyncHttp`：CloudBase HTTP 云函数。
- 网关路径：`/dormsyncApi`。
- 浏览器通过 HTTPS 调用，不直接访问数据库。
- 创建、加入、邀请码轮换和成员管理使用文档数据库事务。
- `createDeviceLink` 和 `claimDeviceLink` 负责短时设备绑定。
- `recoverAccount` 使用长期恢复码创建新设备会话。
- `listDevices` 和 `revokeDevice` 用于设备管理。
- `rotateRecoveryCode` 重新生成恢复码并立即使旧码失效。
- `updateRoomCapacity` 由当前房主在四人寝与六人寝之间切换容量。
- `acknowledgeCapacityNotice` 记录其他成员已经确认房型变更。
- `acknowledgeReleaseNotice` 记录成员已经确认全站版本更新公告。

## 权限

- 普通成员只能修改自己的昵称和状态。
- 创建者可以重新生成邀请码和移除其他成员。
- 成员只能查看和撤销自己账号下的设备。
- 被移除或退出宿舍的令牌立即失效。
- 退出当前设备只撤销该设备会话，不退出宿舍。
- 邀请码更新后旧邀请码不能再加入。
- 六人寝只有在有效成员不超过 4 人时才能降回四人寝。
- 房型变化不修改邀请码。
- 房型变更只向其他成员投递通知，且按成员账号只投递给最先访问的一台设备。
- 全站版本公告按成员上次已读版本累计，只向最先访问的设备投递一次。
- 新成员先保存恢复码，再读取从 `1.0.0` 开始的历史累计公告。

## 同步与到期

- 前端每 5 秒获取一次最新宿舍状态。
- 页面切回前台时立即刷新。
- 云函数读取时将已经到期的睡眠或学习状态恢复正常活动。
- 网络失败时保留最近数据，并显示离线状态。

## 旧账号兼容

- 旧版成员令牌首次请求时，会自动建立 `deviceSessions` 记录。
- 迁移后旧字段 `members.memberTokenHash` 会被清空，避免已撤销会话通过兼容路径重新生效。
- 旧账号不要求重新加入宿舍；恢复码可以在设置页主动生成。
