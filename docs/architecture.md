# 宿舍状态共享站架构

自行部署步骤、CloudBase 资源准备和费用边界见 [自行部署指南](self-hosting.md)。

## 身份

- 每名成员通过创建宿舍或六位宿舍分享号首次加入，成员记录代表稳定账号。
- 服务端为每台设备生成独立随机成员令牌，前端保存在当前浏览器的 `localStorage`。
- PostgreSQL 的 `deviceSessions` 只保存设备令牌的 SHA-256 哈希。
- 已登录设备可以生成 5 分钟有效、只能使用一次的 8 位绑定码。
- 新设备通过绑定码加入同一成员账号，不增加宿舍成员数量。
- 每个账号最多保留 5 个有效设备会话。
- 账号恢复码为一次性展示的 20 位随机值，数据库只保存哈希，可用于旧设备丢失后恢复账号。
- 普通成员忘记恢复码时，房主可以为指定成员生成 10 分钟有效的一次性临时恢复码。
- 房主忘记恢复码时，必须由两名不同成员分别生成一个临时恢复码才能完成恢复。
- 临时恢复码只保存哈希，使用后立即失效；宿舍分享号轮换后，所有未使用临时恢复码同时失效。
- 成员数据读取、状态修改和成员管理操作都必须携带有效设备令牌。

## 数据

CloudBase PostgreSQL 开启 Document 扩展后，使用以下文档集合：

- `rooms`：宿舍名称、宿舍分享号、创建者、四人或六人容量、房型变更通知、ntfy Topic 和关闭状态。
- `members`：成员昵称、身份、恢复码哈希、容量通知投递状态、加入时间和活跃状态。
- `statuses`：每个成员当前唯一的宿舍状态。
- `deviceSessions`：成员账号下的设备令牌哈希、设备标签、最近在线和撤销状态。
- `deviceLinks`：短时设备绑定码哈希、有效期和使用状态。
- `releaseClaims`：全站版本公告的账号级领取和确认记录。
- `securityAttempts`：短密钥和未登录接口的限流窗口，使用客户端 IP 哈希而不保存明文 IP。
- `systemSettings`：存量寝室授权迁移兜底时间、ntfy Topic 惰性初始化抢占记录等系统配置。
- `pushSubscriptions`：成员自己的 Bark 设备、Key 指纹、加密 Key、设备标签和发送状态。
- `joinRequests`：加入请求的幂等记录，避免重复点击或网络重试创建多个成员。
- `temporaryRecoveryCodes`：临时恢复码哈希、目标账号、签发成员、类型、有效期和使用状态。
- `accountRecoveryAudit`：临时码生成和账号恢复结果，仅供房主读取。

## API

- `dormsyncHttp`：CloudBase HTTP 云函数。
- 网关路径：`/dormsyncApi`。
- 浏览器通过 HTTPS 调用，不直接访问数据库。
- 创建、加入、宿舍分享号轮换和成员管理使用文档数据库事务。
- 加入宿舍、设备绑定码和账号恢复接口按 IP 和时间窗限制尝试次数。
- 短密钥比较使用常量时间实现，避免直接字符串比较泄露长度或匹配位置。
- `createDeviceLink` 和 `claimDeviceLink` 负责短时设备绑定。
- `recoverAccount` 使用长期恢复码创建新设备会话。
- `recoverWithAssistance` 校验成员临时码或两名不同成员生成的房主临时码，并在事务内完成恢复。
- `createMemberRecoveryCode` 由房主为指定普通成员生成一次性临时恢复码。
- `createOwnerRecoveryCode` 由普通成员为房主生成一次性临时恢复码。
- `listRecoveryAudit` 只向房主返回最近的恢复记录，不返回恢复码、令牌或设备凭证。
- `listDevices` 和 `revokeDevice` 用于设备管理。
- `rotateRecoveryCode` 重新生成恢复码并立即使旧码失效。
- `updateRoomCapacity` 由当前房主在四人寝与六人寝之间切换容量。
- `acknowledgeCapacityNotice` 记录其他成员已经确认房型变更。
- `acknowledgeReleaseNotice` 记录成员已经确认全站版本更新公告。
- `verifyExistingRoom` 校验存量寝室授权密钥。
- `getNotificationSettings` 向已验证成员返回当前宿舍共享的 ntfy Topic。
- `rotateNotificationTopic` 由房主生成新的通知 Topic。
- `sendTestNotification` 由房主发送测试消息，同一宿舍一分钟最多一次。
- `listBarkDevices` 只返回当前成员的 Bark 设备标签、末 4 位和时间。
- `registerBarkDevice` 校验 Bark Key、先发送测试通知，成功后加密保存。
- `testBarkNotification` 测试当前成员自己的已登记 Bark 设备。
- `removeBarkDevice` 只允许删除当前成员自己的 Bark 设备。
- `adminListRooms` 为本地只读管理站提供寝室级摘要，需要独立管理密钥。

## 权限

- 普通成员只能修改自己的昵称和状态。
- 创建者可以重新生成宿舍分享号、移除其他成员和为普通成员生成临时恢复码。
- 成员只能查看和撤销自己账号下的设备。
- 被移除或退出宿舍的令牌立即失效。
- 退出当前设备只撤销该设备会话，不退出宿舍。
- 宿舍分享号更新后旧分享号不能再加入，未使用的临时恢复码同时失效。
- 六人寝只有在有效成员不超过 4 人时才能降回四人寝。
- 房型变化不修改宿舍分享号。
- 房型变更只向其他成员投递通知，且按成员账号只投递给最先访问的一台设备。
- 全站版本公告按成员上次已读版本累计，只向最先访问的设备投递一次。
- 新成员先保存恢复码，再读取从 `1.0.0` 开始的历史累计公告。
- 只有房主可以轮换通知 Topic 或发送测试通知。
- 每个成员只能读取、测试和删除自己的 Bark 设备，最多登记 5 台。
- 单个普通成员的临时恢复码只能由房主生成；房主恢复必须使用两名不同成员生成的两个临时码。
- 恢复默认保留现有设备；已达到 5 台上限时，自动撤销最近在线时间最早的一台。

## 宿舍通知

- 每个宿舍生成一个 `dormsync-` 前缀的随机 Topic，由服务端保存。
- 创建宿舍响应和普通 `getState` 不返回 Topic；只有通过成员令牌校验的 `getNotificationSettings` 会返回。
- 存量宿舍首次读取通知设置时惰性生成 Topic，并用 `systemSettings` 唯一记录处理并发初始化。
- 成员主动修改状态且 `status`、`note`、`endAt` 至少一项变化时发送一条通知。
- 自动到期、后台同步、创建宿舍、改昵称和设备管理不会发送状态通知。
- 通知失败不回滚状态；接口返回 `notificationWarning`，前端以非阻塞提示展示。
- 所有通知使用 Priority 4；中文标题采用 RFC 2047 Base64 编码。
- 时间统一按北京时间格式化；下一自然日显示“明天 HH:mm”。
- 安静人数只统计当前有效的 `sleep` 和 `focus`，分母使用宿舍容量。
- 成员退出或被移除后只标记房主需要轮换，不自动更换 Topic。
- 成员退出、被移除或寝室清理时删除该成员的 Bark 订阅。
- 撤销普通浏览器设备不会删除 Bark 订阅。

### Bark 通道

- iPhone/iPad 可以选择 ntfy、Bark 或同时使用两种通道。
- Bark 使用每台设备自己的 Device Key，不使用宿舍共享 Key。
- Device Key 使用 AES-256-GCM 加密，密钥来自 `DORMSYNC_BARK_ENCRYPTION_KEY`。
- 数据库只保存 Key 指纹、末 4 位和认证加密后的密文。
- Bark 请求固定发送到 `https://api.day.app/push`，用户不能提供任意推送服务器。
- 同一事件使用相同标题和正文，按宿舍批量发送；重复 Key 在发送前去重。
- Bark 统一使用 `level: "active"` 和 `group: "DormSync"`。
- 响应中的设备 Key、请求体和完整错误响应不写入日志。

Topic 在所选 ntfy 服务上是共享秘密，不提供真正的访问控制。知道 Topic 的人可以订阅、读取或伪造消息。昵称、留言、预计时间和安静人数会发送到部署者配置的 ntfy 服务。

## 寝室授权

- 新建寝室必须提交创建密钥，密钥错误时不写入任何寝室记录。
- 创建密钥和管理密钥只保存在云函数环境变量中。
- 功能上线前创建的寝室在房主首次访问时开始 12 小时验证期限。
- 所有成员在验证完成前只能看到阻塞提示。
- 上线 3 天后仍未被房主触发的存量寝室由 `dormsyncCleanup` 定时清理。
- 清理会同时删除寝室、成员、状态、设备会话、设备绑定、公告领取和该寝室的 Topic 抢占记录。

## 本地工具

- `admin/` 是仅在本机运行的只读管理站，不进入正式静态网站构建。
- `npm run dev:test` 使用内存数据库启动六账号测试环境。
- 六账号测试环境把 ntfy 和 Bark 请求转发到本地收件箱，不访问真实推送服务。
- 测试控制接口只存在于本地测试服务，不进入 CloudBase 云函数。

## 同步与到期

- 前端每 5 秒获取一次最新宿舍状态。
- 页面切回前台时立即刷新。
- 云函数读取时将已经到期的睡眠、学习或外出状态恢复正常活动，并清空旧留言。
- 状态自动恢复正常活动不会触发 ntfy 通知。
- 外出必须填写预计回寝时间；专注学习时间选填。
- 网络失败时保留最近数据，并显示离线状态。

## 旧账号兼容

- 旧版成员令牌首次请求时，会自动建立 `deviceSessions` 记录。
- 迁移后旧字段 `members.memberTokenHash` 会被清空，避免已撤销会话通过兼容路径重新生效。
- 旧账号不要求重新加入宿舍；恢复码可以在设置页主动生成。
